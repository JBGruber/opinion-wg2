# Annotation Task: Annotation of Opinion Measurement Tools

Your task is to annotate the results of a data extraction process focused on identifying 'tools' for opinion measurement.

## Input Data

The extracted data to be annotated here contain both items that fit the definition of a tool (provided below), as well as items that do not fit this definition. 

## Task Description

**Your task** is to annotate the extracted items as follows: (A) assign them to one of the categories specified below, (B) indicate whether the tool or approach is specifically designed for one or more of the three tasks (I) text representation, (II) classification, and (III) target identification, and (C) annotate whether it is provided as reusable, installable software.

**General instruction**: if you do not know the tool do not make assumptions or force a classification, use the unclear categories.

## Definitions

**Definition of a Tool**: For this task, a 'tool' is defined as a measurement framework that incorporates software designed to detect, quantify, or classify concepts in text.

**Opinion Measurement**: For this task, ‘opinion measurement’ is the computational processing of textual data to infer evaluation, belief, or feeling of the text’s author(s) towards a specific subject or target. 

**Definition of Tasks Typically Involved in Opinion Measurement:** Typically, opinion measurement involves three computational tasks: (1) text representation, (2) classification, and (3) target identification. Here, these tasks are defined as:


**(1) Text representation**: Text representation is the computational task of converting natural language into numerical format that machines can process, such as vectors or matrices. Typical approaches of text representation are bag-of-words or embeddings.
**(2) Classification:** Classification is the computational task of automatically assigning one or more labels to an input, based on patterns learned from data or encoded in rules. Labels may be predefined (as in supervised approaches), or emergent (as in unsupervised approaches such as topic modeling). In the context of opinion measurement, classification algorithms are typically applied to units of natural language (e.g., words, sentences, or documents; respectively their numerical representation) to assign evaluative categories, such as sentiment, stance, or emotion.
**(3) Target identification:** Target identification is the computational task of detecting and locating the specific entity, topic, or aspect within text that an expressed opinion, sentiment, or stance is directed at.

Here, we **distinguish** tools based on whether or not they were *specifically designed* to provide a solution for one (or more) of the three tasks. A tool is considered specifically designed for one of the three tasks if its primary purpose — as stated by its authors or as established by its dominant use in the literature — is to provide a solution for that task.
Tools may offer solutions for multiple tasks; some may handle these tasks simultaneously; while others may fail to address any of the tasks specifically.


## Annotation Guidelines

### A: Categories

Assign the category that best fits the item to be annotated. Categories are ordered from general to more specific:

- **approach**: High-level methodologies, frameworks, or conceptual approaches (e.g., "rule-based sentiment analysis", "aspect-based opinion measurement", "deep learning techniques")
- **programming_language**: General programming languages used for implementation (e.g., Python, Java, R)
- **infrastructure**: Platforms, cloud services, or computational infrastructure (e.g., AWS, Hadoop, Spark, distributed computing frameworks)
- **ide**: Integrated Development Environments (e.g., PyCharm, Jupyter Notebook, RStudio)

- **general_library**: General-purpose programming libraries not specific to NLP (e.g., NumPy, Pandas, Matplotlib, ggplot)
- **algorithm**: Learning paradigms, training procedures, or model architectures that define how representations are learned or predictions are made, independent of any specific trained weights (e.g., SVM, Naive Bayes, LSTM, Transformer)
- **model**: Pre-trained models with fixed weights that can be directly used or fine-tuned, typically identified by a name or checkpoint (e.g., BERT-base-uncased, GPT-4, XLM-RoBERTa, domain-specific sentiment classifiers)

- **linguistic_resource**: Lexicons, dictionaries, corpora, or knowledge bases (e.g., SentiWordNet, WordNet, opinion lexicons)
- **data_collection**: Data sources and tools designed specifically for gathering data (e.g., web scrapers, Twitter API, survey platforms, data extraction tools)

- **general_purpose_nlp**: Libraries designed for a range of NLP/text processing tasks (e.g., NLTK, spaCy, Stanford CoreNLP, quanteda)
- **single_purpose_nlp**: Dedicated software tools and libraries designed for one specific NLP task, including, but not limited to opinion measurement, stance detection, aspect based sentiment analysis, POS-tagging (e.g., OpinionFinder, Opinion Observer, TreeTagger)
- **gui_tool**: Tools with graphical user interfaces that don't require programming (e.g., GATE, RapidMiner, text analysis software with visual interface)
- **commercial_api**: Commercial proprietary APIs and cloud services for NLP and sentiment analysis (e.g., Azure Text Analytics, Google Cloud Natural Language API, IBM Watson NLU, AWS Comprehend)

- **other_unclear**: Use this category only if none of the above categories match; do not make assumptions or force a classification


### B I: Text Representation

Is this tool specifically designed for, or typically used for **text representation**, as defined above?

**Mark "yes"** if the tool is specifically designed for, or typically used to produce numerical representations of text, such as word embeddings, sentence embeddings, TF-IDF vectors, or bag-of-words representations. 
**Mark "no"** for tools that are not specifically designed and not typically used for producing text representations (e.g., classification algorithms, data collection tools). Also mark “no” for general-purpose tools such as programming languages (e.g., Python) that can be involved in completing this task but whose primary purpose is not task-specific. Likewise, mark “no” for tools that may generate text representations internally as an intermediate product, but are typically not used to generate these representations as output in itself (e.g., dictionary-based software such as LIWC). 
**Mark "unclear"** if the tool's capabilities in this area are ambiguous, including cases where you do not have enough information or the task-specific purpose of the tool is unclear to you.

- unclear

### B II: Classification

Is this tool specifically designed for, or typically used for **classification**, as defined above?

**Mark "yes"** if the tool is specifically designed for, or typically used to automatically assign one or more labels to an input based on patterns learned from data or encoded in rules. This includes supervised and unsupervised general-purpose classification algorithms applicable to any input, as well as tools specifically designed to classify texts — including, but not limited to, classifiers for sentiment classes, stance labels, topic categories, or part-of-speech tags. 
Mark "no" for tools that produce no categorical, scored, or labeled output (e.g., pure data collection tools). Also mark “no” for general-purpose tools such as programming languages (e.g., Python) that can be involved in completing this task but whose primary purpose is not task-specific. 
Mark "unclear" if the classification capabilities are ambiguous, including cases where you do not have enough information or the task-specific purpose of the tool is unclear to you.
- yes
- no
- unclear

### B III: Target Identification

Is this tool specifically designed for, or typically used for  **target identification**, as defined above? 

Mark "yes" if the tool is specifically designed for, or typically used to identify and locate specific entities, topics, or aspects within text towards which an opinion, sentiment, or stance is directed — including tools dedicated to named entity recognition, aspect term extraction, or semantic role labeling, as well as tools that jointly identify targets and their associated evaluative categories simultaneously (e.g., aspect-based sentiment analysis models or LLM-based pipelines).
Mark "no" for tools that produce no span-level or target-level output — such as pure text representation tools or general-purpose classification algorithms, or document-level sentiment tools that assign a label to the text as a whole without identifying what the opinion is directed at. 

Mark "unclear" if the target identification capabilities are ambiguous, including cases where you do not have enough information or the task-specific purpose of the tool is unclear to you.


- yes
- no
- unclear



### C: Software

Is the tool’s name associated with a specific, installable piece of software designed for general use — including graphical user interfaces, command line interfaces, libraries, and packages? 
Mark "yes" if the name refers to a concrete software product that can be installed and run on an end user's machine — such as a Python library, R package, command-line tool, or GUI application (e.g., VADER, TextBlob, Stanford CoreNLP, LIWC, NLTK).

Mark "no" if the name refers to:
a general algorithm or method that is not itself a software product (e.g., SVM, Naive Bayes, TF-IDF, bag-of-words, decision tree) — even if many software implementations of it exist,
a service or tool that only runs on the provider's infrastructure and is accessed remotely (e.g., web APIs, online platforms),
a one-off analysis scripts distributed alongside a specific paper, or resources not packaged as reusable, installable tools.

Mark "unclear" if it is ambiguous whether the name refers to a specific installable software product or a general algorithm/approach, or if you do not have sufficient information.

- yes
- no
- unclear
